# PlusAura / Продуктовые дашборды

Три интерактивных представления для портфолио аналитика. Дашборд работает офлайн, без сервера, Python-пакетов, CDN и внешних запросов.

## Как открыть

Скачайте [`index.html`](index.html) через **Download raw file** и откройте двойным щелчком в браузере. GitHub показывает исходный HTML, а не запущенный дашборд. Весь код и демонабор встроены в один файл.

## Представления

| Дашборд | Метрики |
| :--- | :--- |
| **Обзор продукта** | DAU, WAU, MAU, DAU/MAU, сессии на активного пользователя, дневная динамика |
| **Удержание** | Exact-day D7/D30, недельная когортная таблица, сравнение групп по тренировкам первой недели |
| **Прогресс** | Завершённые тренировки, минуты, доля активных пользователей с ≥3 тренировками за 7 дней |

Период и источник привлечения фильтруют все представления. Метрики можно выгрузить в CSV. Прогресс здесь означает активность внутри продукта, а не медицинскую оценку здоровья.

## Данные и честная интерпретация

По умолчанию используются **600 синтетических пользователей**; набор воспроизводится с seed `20261101`. Он не содержит реальных клиентов и не является доказательством результатов из резюме. Значения удержания, относительного эффекта и частоты сессий вычисляются по событиям, а не зашиты в интерфейс. Сравнение групп — наблюдаемая связь, не причинный эффект и не A/B-тест.

Исходный backend приложения пока не собирает полноценный поток сессий и не различает завершение тренировок в формате этого контракта. Дашборд не подключён к production-БД автоматически. Для реальных расчётов нужны проверенная выгрузка событий и дата последнего полностью наблюдаемого дня.

Через поле **«Свои данные»** можно загрузить обезличенный JSON до 10 МБ:

```json
{
  "observed_until": "2026-09-30",
  "users": [{"id": "u1", "signup": "2026-09-01", "segment": "Органика"}],
  "sessions": [{"id": "s1", "user_id": "u1", "date": "2026-09-08"}],
  "workouts": [{"id": "w1", "user_id": "u1", "date": "2026-09-02", "duration": 30, "completed": true}]
}
```

Используйте полную историю с момента регистрации; все даты — дни UTC. Дата `observed_until` задаётся явно: отсутствие событий после неё не означает отток. Идентификаторы строковые, уникальные в пределах каждой таблицы. Повторные ID, некорректные даты, неизвестные пользователи, отрицательные длительности и события вне окна наблюдения отклоняются. Имена, контакты и показатели здоровья не нужны. Загрузка обрабатывается локально и не отправляется на сервер.

## Определения

- **DAU:** уникальные пользователи с сессией в последний выбранный день.
- **WAU / MAU:** уникальные пользователи с сессией в последние 7 / 30 дней включительно. История до начала отображаемого периода учитывается.
- **D7 / D30:** сессия ровно на 7-й / 30-й день после регистрации. Знаменатель — только регистрации выбранного периода с завершённым сроком наблюдения.
- **Когортная таблица:** неделя регистрации начинается в понедельник; Wn = хотя бы одна сессия в дни `[7n, 7n+6]` после индивидуальной регистрации. Незавершённое для всей когорты окно отображается как «—», а не 0%.
- **Гипотеза тренировок:** завершённые тренировки в дни 0–6; сравнение D30 только для зрелых регистраций. Разница в процентных пунктах и относительный эффект показаны отдельно; деление на нулевую базу не производится.
- **Цель:** ≥3 завершённых тренировок за 7-дневное окно от начала периода; знаменатель — пользователи с сессией в том же окне. Последнее неполное окно помечено.
- **Пустой знаменатель:** «—», а не 0%.

## Исходники и проверки

| Файл | Назначение |
| :--- | :--- |
| [`index.html`](index.html) | Готовый автономный дашборд |
| [`template.html`](template.html) | HTML/CSS и интерфейс |
| [`metrics.js`](metrics.js) | Валидация и расчёт метрик |
| [`build_demo.py`](build_demo.py) | Воспроизводимая сборка с синтетическими событиями |
| [`test_metrics.cjs`](test_metrics.cjs) | Тесты знаменателей, дубликатов, сегментов и окон наблюдения |
| [`test_dashboard.cjs`](test_dashboard.cjs) | Проверка выполнения собранного HTML, фильтров и вкладок в минимальной DOM-модели |
| [`product_metrics.sql`](product_metrics.sql) | Аналогичные расчёты на PostgreSQL с CTE и оконной функцией |

Из корня репозитория:

```bash
python analytics/build_demo.py
node --test analytics/test_metrics.cjs analytics/test_dashboard.cjs
```

Python 3.10+ и Node.js 18+ нужны только для сборки / тестов. Для просмотра достаточно браузера.

SQL создаёт отдельную схему `plusaura_analytics`, не меняя таблицы приложения. Запросы являются шаблоном для проверенной выгрузки, а не автоматическим подключением HTML к БД. Настройте параметры дат и сегмента; сессии и тренировки должны быть не раньше регистрации и не позже `as_of`.
