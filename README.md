## Идея проекта

PlusAura объединяет несколько пользовательских сценариев в одном приложении: планирование дня, учёт питания, запись тренировок и просмотр прогресса. Проект позволяет проследить путь от продуктовой идеи и экранов до серверных API.

## Возможности

| Раздел | Что реализовано в исходном коде |
| :--- | :--- |
| **Календарь** | Просмотр и добавление задач |
| **Питание** | Учёт приёмов пищи и экран плана питания |
| **Тренировки** | Запись тренировок и отображение активности |

| **Генерация рекомендаций** | Серверный маршрут генерации плана питания |

## Продуктовые дашборды

Добавлен отдельный [аналитический модуль](analytics/README.md) с тремя представлениями: **обзор продукта**, **когортное удержание** и **прогресс тренировок**.

- DAU / WAU / MAU, частота сессий и DAU/MAU.
- Exact-day D7/D30 Retention, недельные когорты и сравнение групп по тренировкам первой недели.
- Фильтры по периоду и источнику привлечения, загрузка обезличенного JSON, экспорт метрик CSV.
- [PostgreSQL-запросы](analytics/product_metrics.sql) с CTE и оконной функцией.

**[Скачать автономный дашборд](analytics/index.html)** через Download raw file и открыть в браузере. Он работает без установки. По умолчанию используются явно обозначенные синтетические данные; результаты из резюме не подставляются в графики. Модуль не подключён к production-БД автоматически и не встроен в Flutter-экран.

## Запуск клиентской части

Нужны установленный Flutter SDK и совместимый Dart SDK — ограничения версий указаны в `pubspec.yaml`.

```bash
git clone https://github.com/nagdarnik/PlusAura.git
cd PlusAura
flutter pub get
flutter run
```

Работа сетевых функций зависит от настройки backend, базы PostgreSQL и внешнего сервиса генерации. Запуск клиента сам по себе не настраивает эти компоненты.

## Текущий статус

Это прототип: часть экранов использует демонстрационные данные. В `analytics/` опубликованы автономные продуктовые дашборды и SQL-расчёты с описанной методикой. A/B-анализ и Power BI-отчёт здесь пока не опубликованы.
